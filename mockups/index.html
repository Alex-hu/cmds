原型 B · fzf 式即时过滤
打开即一个输入框，输入即模糊过滤（子序列打分），↑↓ 选，Enter 详情。无 tab 概念，来源词可直接当过滤词（如 conda:）。
适合："我知道命令名，查它的来源/版本"——最高频场景。代价：浏览发现能力弱。
原型 C · 分栏浏览器
左栏来源树（conda 展开出各环境），中栏命令列表，右栏详情常驻实时刷新。结构像 VS Code 侧边栏。
适合：闲逛式探索"这台机器都装了什么"。代价：小终端窗口（<100 列）布局紧张。

决策点（请逐项给结论）

  • 主界面选型：A / B / C 三选一；也可以选组合（如默认 B、cmds browse 进 A 或 C）。
  • conda 环境交互：A 的 [ ] 循环、C 的左栏环境树、B 的无环境概念（靠过滤词），哪种顺手？
  • 同名合并展示：All 视图默认合并（×N 徽标）还是平铺？
  • 详情呈现：A/B 的弹层 vs C 的常驻侧栏？
